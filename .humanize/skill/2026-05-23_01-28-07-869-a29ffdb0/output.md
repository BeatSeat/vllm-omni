CORE_RISKS:
- Reference parity may be overestimated if comparison is component-level only. End-to-end parity needs same text normalization, reference audio, emotion inputs, sampling params, stop token handling, and output postprocessing.
- Current tests can pass with synthetic sine reference audio, but that does not validate real voice cloning, speaker similarity, pronunciation, or emotional fidelity.
- Offline and online paths may not be equivalent: offline examples pass file paths, online resolves base64/data URLs into decoded arrays. Both must hit the same `additional_information` contract.
- `async_chunk=false` is architecturally reasonable for S2Mel flow matching, but streaming `/v1/audio/speech` becomes Б─°full audio emitted as one stream payload,Б─² not true low-latency streaming.
- L4 Colab may expose memory/runtime failures not seen on L40. The deploy YAML says verified on 1x L40 48GB, while the draft targets L4.
- Quality eval can produce false confidence if ASR compares generated speech against prompts without language-aware normalization, punctuation handling, Chinese segmentation, and failed-audio filtering.
- Commit/push before full validation risks baking in noisy debug logging and brittle assumptions, especially around dtype/device fixes and HuggingFace dependency compatibility.

MISSING_REQUIREMENTS:
- Define exact Colab setup: repo checkout branch, commit SHA, dependency install command, model cache location, HuggingFace auth/token expectations, and disk budget.
- Require real reference audio fixtures for English and Chinese, not only generated sine waves.
- Specify output manifest format under `/content/index-tts-outputs/{offline,online}/`: prompt, ref audio id, mode, seed, params, sample rate, duration, RTF, WER/SIM/UTMOS, error status.
- Include response-format matrix: offline tensor/WAV, online `wav`, online `pcm` streaming fallback, and invalid formats.
- Add negative API tests: missing `ref_audio`, bad data URL, empty input, malformed `emo_vector`, invalid `emo_alpha`, unsupported audio type, long text.
- Add concurrency requirements, even if non-streaming: at least 4 parallel online requests to catch shared-state or connector issues.
- Add reproducibility rules: fixed seed, deterministic mode expectations, acceptable waveform tolerance, and when nondeterminism is allowed.
- Include cleanup/logging requirements so Colab artifacts are retained but logs are not dominated by per-step debug output.

TECHNICAL_GAPS:
- Stage 0 emits accumulated mel codes and Stage 1 consumes full sequence. The plan should explicitly validate no duplicated/truncated codes after output consolidation.
- S2Mel uses `.item()`, `.tolist()`, CPU transfers, and verbose shape logging in hot/near-hot paths. Fine for debug, risky for performance benchmarks.
- Sample-rate expectations need tightening: config defaults mention 24000 in places, tests/docs say 22050, BigVGAN path returns 22050.
- Emotion text depends on Qwen emotion model availability. Fallback behavior must be tested and documented when that submodel is absent.
- CUDA kernel fallback and semantic codec `strict=False` should be treated as compatibility modes with visible warnings, not silent success.
- Online serving builds prompt with `prompt_token_ids=[1]`; acceptance should verify this stays compatible with talker preprocess and does not hide prompt-length issues.
- Bench integration is not guaranteed by examples/tests. `benchmarks/tts/bench_tts.py` may need explicit IndexTTS2 config/preset support.

ALTERNATIVE_DIRECTIONS:
- Validate reference-first in Colab: run official `cache/index-tts` and vLLM-Omni side by side on the same inputs. Higher confidence, slower setup.
- Ship non-streaming only first: offline plus online `stream=False` WAV, document `stream=True` as fallback. Lower risk, less impressive latency story.
- Add a small golden-audio regression set: real ref audio plus fixed prompts and loose metric thresholds. Better long-term guardrail, needs artifact management.
- Use benchmark CLI as the main validation harness instead of ad hoc scripts. More repeatable, but requires adding IndexTTS2 dataset/model config.
- Delay push until Colab passes, then squash/debug-clean. Cleaner branch history, but slower collaboration if others need the branch immediately.

- Code is debug-log-clean, formatted/linted, committed, and pushed only after the selected acceptance suite passes.
